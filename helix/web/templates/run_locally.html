Local serving Ollama · Open Interpreter · LM Studio · llama.cpp

The workers sit next to the person, not in a rented cloud

C7X-IO does not host your production model and does not replace the person at the desk. It returns a QLoRA adapter you download. You load it beside the same open instruct base you trained, then serve it with Ollama, Open Interpreter, LM Studio, llama.cpp, or the PEFT script in the zip — on the PC that already sits in the cabin.

That is how an MSME breaks the hire-or-stall bind without sending GST bills or buyer photos to a hosted chat box. See the India MSME cases for the person these workers sit beside.

What is in the trained zip

The package is an adapter, not a rented endpoint and not a merged 7B–30B dump:

  • qlora/ — the adapter weights C7X-IO trained on your gold library.
  • tokenizer/ — the tokenizer files used at train time.
  • meta.json — includes base_model, the Apache-2.0 or MIT instruct checkpoint you must load against.
  • load_adapter.py — a PEFT loader. Test a prompt, or merge to a folder.

Catalog bases are Apache-2.0 or MIT instruct models up to 30B. The default is Qwen2.5 7B Instruct. Use the same base at serve time that you trained on.

1. Smoke-test with the PEFT script

Unzip the package. From that folder:

pip install torch transformers peft accelerate
python load_adapter.py --prompt "Buyer sent a photo: left sleeve hole after wash. PO 391. Refund or remake?"

To produce a single folder for conversion tools:

python load_adapter.py --merge-to ./merged --base Qwen/Qwen2.5-7B-Instruct

If meta.json already names the base, you can omit --base.

2. Serve with Ollama

Ollama wants a GGUF. After you merge:

  1. Convert ./merged to GGUF with the converter your serving stack documents (llama.cpp’s conversion script is the usual path).
  2. Write a Modelfile that points at that GGUF and sets a short system line for the role.
  3. Create and run the local model.
FROM ./returns-desk-q4.gguf
SYSTEM You are the returns desk for one knitwear exporter. Classify the defect, decide refund, remake, or reject, and write a Tamil + English floor note. If the PO is missing, ask one question. Do not invent a credit note.

PARAMETER temperature 0.1
ollama create returns-desk -f Modelfile
ollama run returns-desk

The same Ollama model is then an OpenAI-compatible server on http://127.0.0.1:11434/v1 for anything else on the LAN that should not leave the building.

3. Drive it from Open Interpreter

Open Interpreter can talk to a local model instead of a hosted one. Point it at the Ollama (or llama.cpp) server that is already running the C7X worker:

export OPENAI_BASE_URL=http://127.0.0.1:11434/v1
export OPENAI_API_KEY=ollama
interpreter --local --model returns-desk

Use this when the role must take actions on the same PC — rename a scan, fill a CSV, open the day’s returns folder — not only reply in a chat window. Keep the system prompt identical to the role you trained. The weights hold the judgment; the harness holds the tools.

4. LM Studio, llama.cpp, and similar tools

Any local runtime that can load a GGUF or a PEFT adapter will do. Typical pairings:

  • LM Studio — import the GGUF, expose the local server, call it from your shop tools.
  • llama.cpp — llama-server for an OpenAI-compatible endpoint on the LAN, useful for a second terminal in the accounts room.
  • A small OpenAI-compatible proxy you already run — same idea: the model file is yours, the URL is localhost.

C7X does not lock you to one of these. It produces the adapter. The harness is a choice you make after download.

Honest limits

  • The zip is a QLoRA adapter. If your tool cannot load PEFT, merge first, then convert.
  • You must have a license to the base. C7X only trains Apache-2.0 and MIT instruct models.
  • A 7B Q4 GGUF is the MSME default. 14B and 30B need more RAM or a dedicated GPU.
  • C7X is not a hosted inference vendor. If the shop PC is off, the worker is off.
